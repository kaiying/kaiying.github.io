FFLogs 對帳建議與待驗證項目 ​

2026-09-10 文件 review：實作進度以 doc/project-progress.md 為唯一入口，現行公式以 公式與限制 為準。建議不代表已實作，也不以尚未核實的公式宣稱 FFLogs 官方規則。

已修正的舊建議 ​

  • 撤回全面移除 addConsumedKnownCapacityRemainder 的要求。 v54 已將中間學派 barrier 辨識為 781，容量為同 frame 90A6 回復量的 125%；提前移除可作為逐目標耗盡證據，F36 則是 HoT。自然到期不計未耗餘額，覆蓋與多盾情境仍須個別驗證，不能把所有狀態移除概括為破盾或全部排除。
  • 撤回統一改寫所有 overheal 分母的要求。 戰鬥摘要使用 overheal / raw healing；治療表與 FFLogs 未含 mitigation 子口徑使用 overheal / (raw healing + consumed absorbs)。兩個欄位用途不同，不能全域取代。
  • CPM 純 buff／utility 施放已納入。 parserVersion 25 已移除必須有傷害或治療效果的條件，仍排除自動攻擊並去重 AoE；後續只追查具體漏記事件。
  • 戰鬥邊界差異須逐事件對齊。 不以本案例約 0.67 秒差距作通用修正量，也不把開怪倒數直接當成戰鬥開始。

治療對帳的有效工作 ​

  • 保留 v54 中間學派 784,100、AST absorbs 921,814 的校準紀錄；AST 與本案例 FFLogs 的剩餘盾差為 F34 15,036，仍需完整容量與狀態證據。
  • SCH 三筆完全吸收事件缺口合計 82,390，本地 type 22 damage amount 與 HP 變化均為 0；維持已知限制。不得以報告差額或固定倍率回填。
  • 繼續核對 effective healing、同 server frame HP snapshot 與 action sync 配對。以逐事件證據判定差異，不把 comparator 差異總數當成根因分類。
  • Comparator 缺失／非有限數值檢查及六種分類已由工作包 A 完成並整合；未提供的 baseline 欄位顯示未比較。CI 第一版已採必要 fixture 全數驗收；下一步分類 Healing pending 與取得逐事件 baseline，完整私人報告 gate 仍待資料。

減傷：保留總量公式，撤回不守恆的分配公式 ​

以下僅為已知乘法減傷且資料完整時的數學模型，尚非本專案已實作或已驗證的 FFLogs 歸因規格。令 D0 為未減傷傷害、D 為套用減傷後但扣盾前的傷害：

text
D = D0 × product(1 - r_i)
總減傷量 = D0 - D
各技能歸因量的合計必須等於總減傷量

原建議將每項歸因設為 D0 × r_i，多減傷疊加時不守恆：原傷害 100、兩個 10% 減傷，承傷為 81，總減傷為 19，舊公式卻分配出 20。撤回該逐技能公式；分攤策略須另以來源與逐事件案例驗證。

HP loss 可能已扣盾、受 overkill、治療與同 frame 快照影響，不能直接代入 D。傷害類型、敵方 debuff、免疫、狀態覆蓋與盾的先後順序也須確認。證據不足時保留未知；完整模型驗收前不新增「含減傷 HPS」切換。

rDPS 後續工作 ​

倍率 buff 的 log-weight、target debuff matching、Crit／DH 條件模型與 direct／DoT event kind 仍待完成；詳見 rDPS 跟進計畫。它們屬 Healing 主線穩定後的實作，不再另列為立即 P0。

技能 ID、數值與套用方向必須符合 doc/buff-metadata-policy.md，不能直接把舊建議中的技能清單當成已驗證 metadata。Crit／DH 模型須處理必爆必直、DoT 與資料不足，不能只憑本場觀測比例假裝已知角色屬性。
