FFXIV Log Analyzer — FFLogs 演算法對齊與精準度優化建議 ​

文檔定位：本文件針對 ffxiv-my-logs 專案在比對 FFLogs 基準（XDt7a138MhLqNbkx / fight=last）時產生 59 項數值偏差的瓶頸，進行深入的底層封包解析、數學公式剖析，並提供具備權威依據的公式修復建議與實作指南。

一、 現況瓶頸與偏差根源剖析 ​

在執行 npm run compare:fflogs 比對「熱舞綠光」通關基準場時，本地解析器與 FFLogs 產生了 59 項數值差異。這些差異並非隨機浮動，而是源於以下 7 大核心公式與事件處理盲點：

二、 核心公式權威修訂指南 ​

1. 戰鬥邊界與時間分母（Fight Duration & Timeline） ​

  • 問題現況：本地 Pull 判定長度為 601.00s，而 FFLogs 計算 HPS/DPS 之戰鬥有效時間為 600.33s。
  • FFLogs 官方口徑： $$\text{Fight Duration} = \frac{T_{\text{end}} - T_{\text{start}}}{1000}$$
    • $T_{\text{start}}$：第一筆有效戰鬥互動事件（對 Boss 的傷害技能 / 讀條完成 / 開怪倒數訊號）。
    • $T_{\text{end}}$：Boss HP 歸零（Line 37/38 HP=0、Line 25 死亡事件或 Director Control 戰鬥結束封包）。
    • 重要概念：FFLogs 表尾顯示的 601.1s Total Active 是介面顯示值，所有玩家的 DPS / HPS / rDPS / CPM 均以統一的 Fight Duration（600.33s）為分母，不可使用個別玩家的 Active 時間。

2. 治療、護盾與過量計算（Healing, Absorbs & Overheal） ​

(1) 過量治療百分比（Overheal %） ​

  • 錯誤公式：$\text{Overheal%} = \frac{\text{Total Overheal}}{\text{Total Raw Healing}}$
  • FFLogs 官方正確公式： $$\text{Overheal%} = \frac{\text{Total Overheal}}{\text{Total Raw Healing} + \text{Consumed Absorbs}} \times 100%$$

    說明：FFLogs 將「被實際消耗的護盾量（Absorbs）」視為 0% 過量的有效治療，併入分母計算。

(2) 護盾吸收量（Absorbs）修正（解決占星 +99.8 萬虛高） ​

  • 錯誤邏輯：在 statusProcessor.ts 的 addConsumedKnownCapacityRemainder 中，當護盾狀態在時間結束前被移除（Line 30），程式碼誤將剩餘護盾量（$\text{Capacity} - \text{Consumed}$）全部補進吸收量。
  • FFLogs 官方正確規則： $$\text{Absorbed Damage} = \min(\text{Shield Capacity Remaining}, \text{Expected Damage} - \text{Actual HP Loss})$$
    • 未被傷害擊破而自然消失、被新護盾覆蓋刷新、或致死 Overkill 的剩餘護盾量，絕對不計入 Absorbs。
    • 必須廢除「狀態提前消失就補滿護盾剩餘容量」的推測邏輯。

(3) 減傷治療口徑（Mitigations，options=16384 vs options=0） ​

  • FFLogs 預設主表（options=16384）包含減傷貢獻： $$\text{Default Healing Amount} = \text{Effective Heal} + \text{Consumed Absorbs} + \text{Mitigated Damage}$$
  • 單一減傷技能貢獻計算公式： $$\text{Unmitigated Damage} = \frac{\text{Actual Damage Received}}{\prod_{k=1}^m (1 - r_k)}$$ $$\text{Mitigated Amount}_j = \text{Unmitigated Damage} \times r_j$$ （其中 $r_j$ 為第 $j$ 個減傷技能的減傷比例，例如牽制 10%、雪仇 10%、野戰治療陣 10%）。

3. 團隊增傷貢獻歸因（rDPS / aDPS / nDPS 公式） ​

(1) 多團輔乘法疊加的對數歸因模型（Logarithmic Normalization） ​

當多個百分比增傷 Buff 同時存在時（例如 $m_1 = 1.05, m_2 = 1.06, m_3 = 1.03$）：

  • 總增傷乘數：$M = \prod_{i=1}^n m_i$
  • 該事件的總外部增傷量：$L = \text{EventDamage} - \frac{\text{EventDamage}}{M}$
  • 各 Buff 提供者的分配份額（FFLogs 官方 Kihra 演算法）： $$\text{Share}_i = L \times \frac{\ln(m_i)}{\ln(M)}$$

    優勢：對數模型保證了任意組合下的分配對稱性與一致性，避免線性加權在多 Buff 疊加時產生偏差。

(2) 目標 Debuff 型團輔（Target-Debuff rDPS） ​

  • 修復重點：在 rdps.ts 中，除檢查來源玩家身上的 Buff（buff.targetId === damageEvent.sourceId）外，必須同時匹配目標身上的 Debuff（debuff.targetId === damageEvent.targetId）。
  • 關鍵技能清單：
    • 學者：連環計（Chain Stratagem，ID: 0x4C5，+10% 暴擊率）
    • 忍者：毒盛（Dokumori，ID: 0xAA9，+5% 易傷）/ 攻其不備（Trick Attack）
    • 雙劍/舞者/占星：各類目標易傷或單體舞伴/發卡歸因。

(3) 暴擊 / 直擊型團輔（Crit / Direct Hit Buffs）條件機率模型 ​

不再使用靜態常數，而是根據每筆 Damage Event 的實際命中標記（Flags）進行分解：

  • 若事件未暴擊：連環計 / 戰鬥連禱貢獻為 $0$。
  • 若事件暴擊：
    • 設目標天然暴擊率為 $C_{\text{base}}$，暴擊傷害倍率為 $M_{\text{crit}} = 1.4 + \text{CritStatBonus}$。
    • 暴擊團輔帶來的條件增傷貢獻： $$\text{Crit Share} = \text{EventDamage} \times \left(1 - \frac{1}{M_{\text{crit}}}\right) \times \frac{C_{\text{buff}}}{C_{\text{base}} + \sum C_{\text{buff}}}$$

4. 技能施放數與 CPM（Casts / CPM） ​

  • 問題現況：目前僅統計造成傷害或治療的技能，遺漏了非傷害型能力技（如鐵壁、真言、疾跑、挑釁、身形切換等）。
  • FFLogs 官方定義：
    • 統計所有有效的 NetworkAbility (21) / NetworkAOEAbility (22) 事件。
    • 排除：自動攻擊（Auto-Attack，Ability ID 0x07, 0x08）。
    • AoE 去重規則：同一時間戳 + 同一施法者 + 同一 Ability ID 只計為 $1$ 次 Cast。
    • $\text{CPM} = \frac{\text{Total Valid Casts}}{\text{Fight Duration Seconds} / 60}$。

三、 四階段精準實作路線圖 ​

【階段一】基礎數值與護盾除錯 (P0 · 立即修正) ​

  1. 修正 Overheal% 分母：改為 totalOverheal / (totalRawHealing + totalShielding) * 100。
  2. 移除護盾偽消耗邏輯：移除 statusProcessor.ts 中的 addConsumedKnownCapacityRemainder，護盾消耗完全以傷害事件中實際發生的 HP 阻擋為唯一來源。
  3. 執行比對驗證：跑 npm run compare:fflogs，確認占星與學者 Absorbs 偏差大幅收斂。

【階段二】rDPS 對數模型與目標 Debuff (P0) ​

  1. 重構 src/parser/report/rdps.ts：
    • 實作對數分配函式 splitEstimatedExtraDamageLogarithmic。
    • 加入目標 Debuff 匹配邏輯（支援連環計與毒盛）。
  2. 擴充 buffMetadata.ts：完整收錄連環計、毒盛、戰鬥連禱、技巧舞步、惡魔之舞等全職業 7.0 團輔清單。

【階段三】減傷與完整 Healing 視圖 (P1) ​

  1. 實作減傷追蹤器（Mitigation Tracker）：
    • 在承傷事件時，比對目標當前啟用的防禦 Buff（雪仇、牽制、野戰治療陣、光之幕簾等）。
    • 依乘法減傷公式反推未減傷原始傷害，計算各減傷技能貢獻。
  2. 支援 FFLogs 雙口徑切換：在前端提供 預設 (含減傷) 與 純治療+護盾 兩種模式。

【階段四】戰鬥邊界與 CPM 完善 (P1) ​

  1. 精準戰鬥起止點：以首個戰鬥技能開始，以 Boss HP=0 / 死亡封包精確截斷，縮減 0.67s 誤差。
  2. 非傷害技能 Cast 納入：補齊全技能 Cast 統計與 AoE 去重，對齊 CPM。
