Overlay 對帳功能 ​

目的 ​

用 ACT overlay 的統計畫面作為對照組，檢查本地 parser 對同一份 log、同一把戰鬥算出的 DPS / HPS / 傷害 / 治療口徑是否一致。

目前第一個案例是 pic/success.png，對應 logs/Network_30207_20260811.log 的「熱舞綠光」通關場；FFLogs report XDt7a138MhLqNbkx 的 fight=last 已確認對應本機 pull 14（本機 log 在該通關後仍有其他 pull，因此不是本機最後一筆）。

執行 ​

bash
npm run compare:overlay

也可以指定其他案例檔：

bash
npm run compare:overlay -- overlay/cases.json

工具會優先讀 public/data 已產生資料；如果該 log 還沒有被 npm run parse 產生，就會直接讀原始 log 對帳，不會清掉或重寫網站資料。

檔案 ​

  • overlay/cases.json：設定 log、baseline、戰鬥名稱、選第幾把。
  • overlay/baselines/*.json：人工抄錄 overlay 顯示值。34k、20.2M 這種縮寫會依 overlay 顯示精度容許四捨五入誤差。
  • src/parser/tools/compareOverlay.ts：CLI 入口。
  • src/parser/validation/overlayComparison.ts：欄位對帳邏輯。

目前已對帳欄位 ​

  • 戰鬥：名稱、時間、Total DPS、Total HPS。
  • DPS 表：DPS、D%、Damage、Swing、直擊率、爆擊率、爆直率、MaxHit、死亡數。
  • HPS 表：HPS、H%、Healed、Eff.Heal、D.Shield、OverHeal、O.H。

已知限制 ​

  • 目前不做 OCR，baseline 需要人工抄錄 overlay 數值。
  • 第一版只對 screenshot 可見列；overlay 畫面未顯示的治療列不會被視為錯誤。
  • 正式 parser 已將 Limit Break 拆成獨立 Limit Break 列；若仍有差異，代表 log 內事件筆數或 baseline 截圖口徑需要追查。
  • 若對帳差異集中在 DPS / HPS，但總量接近，通常要優先檢查戰鬥起訖時間。
  • 若差異集中在 Swing / MaxHit / Limit Break，通常要檢查 ACT 與本地 parser 的事件歸屬口徑。

20260811 success.png 對帳現況 ​

最後更新：2026-08-29。

執行：

bash
npx tsx src/parser/tools/compareOverlay.ts

parserVersion 51 的治療與傷害公式沿用 v47；目前重跑結果為 compared=1, differences=67, invalid=0。

已確認的改善與限制：

  • Limit Break 已從玩家傷害拆成獨立列，總傷仍包含 LB。
  • 已確認 ACT overlay 截圖的 Healed 口徑是 Eff.Heal + OverHeal + D.Shield，也就是 raw healing + direct shield。
  • overlay 對帳使用 (raw healing + direct shield) / active damage duration；網站主表則採 FFLogs 優先的 (effective healing + effective shield estimate) / pull duration，兩者刻意分離。
  • 網站治療表的 duration 是 pull end - pull start；overlay 對帳工具為了貼截圖，另用 active damage duration。
  • 有效護盾(估) 仍是本地估算值，不等於 overlay 的 D.Shield / FFLogs absorbs。
  • 已修正 owner mapping：OwnerID 現在會套用到有 BNpc metadata 的寵物/地面效果，讓 地星、卡邦庫爾-黃寶石、熾天使 這類來源歸回玩家。
  • 已移除不是 barrier 的 F38 太陽星座與 764 中間學派 self buff，加入 F34 建築神之塔；762 / 763 只阻擋多盾誤歸屬，不直接製造 absorb。
  • player damage 已排除敵方與 E0000000 環境來源的 DoT；本案例移除 212,413 假團隊傷害後，總傷為 105,516,448，與 FFLogs 105,549,649 差 -33,201。
  • F36 只有同來源、同目標的 781 中間學派仍有效時才建立護盾容量；F34 不再從 action line 合成全隊狀態。
  • 可用 npm run compare:overlay -- --fresh 強制直接解析原始 log，避免誤讀舊 generated data。

仍需追查的主要差異：

  • 戰鬥時間：排除開戰前仙女純治療、並在主目標 HP 歸零時結束後，本地 pull duration 已由 10:51 收斂為 600.997s，接近 FFLogs／overlay 的約 10:00。
  • Limit Break：本地 kill pull 只抓到 1 筆 生者必滅，overlay baseline 是 2 筆。
  • FFLogs options=0 精確基準：草莓香草可頌 8,212,154（effective 7,275,304 + absorbs 936,850）；草灰妲 7,049,289（effective 3,964,614 + absorbs 3,084,675）。parserVersion 44 本地含盾分別為 7,950,451、6,982,316，與 FFLogs 差 -261,703、-66,973；學者 absorbs 3,087,342 僅差 +2,667。
  • parserVersion 51 AST D.Shield 保守估算為 394,454（F36 256,740 + F34 114,290 + 天星交錯 23,424），低於 overlay 895,400／FFLogs 936,850；缺口不以全隊合成狀態或報告常數回填。
  • Overlay raw Healed 仍有差異；原因主要是 effectId=0 無法完整拆分的 tick。
  • Hits / Swing / Crit / DH：overlay comparator 的比率只用有 action flags 的事件作分母，但 Swing 仍有大量差異，ACT 是否包含 miss／zero／其他 swing type 尚未確認。
  • MaxHit 技能名稱：部分技能名稱與 overlay 簡稱不同，例如 天道回返雪月花 vs 天道回返，需做顯示名稱 normalize，而不是改原始事件名。

公式調整計畫 ​

M1. 對帳工具可信度 ​

Status: Partial

目標：先確認 baseline 與本地 pull 是同一把，避免拿不同 encounter 修公式。

  • [x] 建立 npm run compare:overlay 對帳入口。
  • [x] 建立 pic/success.png 對應的人工 baseline。
  • [x] 對帳工具使用 active damage duration 估算 overlay 顯示分母。
  • [x] 支援 --fresh 強制直接 parse，排除 generated data 陳舊干擾。
  • [ ] 在對帳輸出增加 local pull 摘要：start/end、pull duration、active damage duration、total damage、total raw healing、total healed。
  • [ ] 對 baseline 加上可選的 encounter duration / total damage / total healed 快速檢查。
  • [ ] 補一個「候選 pull ranking」輸出，列出同 boss 最接近 overlay total damage / duration 的 pulls。

M2. 戰鬥時間分母 ​

Status: Planned

目標：釐清網站主表是否要使用 ACT overlay 相容分母。

  • 新增 activeDamageDurationSeconds 到 PullSummary。
  • DPS 對帳用 active damage duration；網站主表先保留 pull duration，旁邊顯示計算時間差異。
  • 若 overlay 對帳穩定，再決定主 DPS 是否切換為 active damage duration。

M3. Healing 來源覆蓋率 ​

Status: In progress

目標：先把治療分子對齊 overlay，尤其是草莓香草可頌 raw healing 缺口。

  • [x] 確認 overlay Healed = Eff.Heal + OverHeal + D.Shield = raw healing + direct shield。
  • [x] 將 overlay comparison 的 HPS / Healed / H% / OverHeal% 改成含盾口徑。
  • [x] 修正 owner mapping，讓 地星、卡邦庫爾-黃寶石、熾天使 歸回玩家。
  • [x] 建立 healing-only debug CLI，輸出 by player / by ability / raw / effective / overheal / shield。
  • [x] 專查草莓香草可頌 raw healing 缺口；修正後由 13.81M 提升至 19.64M。
  • [x] 修正 HoT abilityId=0 把 AST tick 歸到 DPS / tank 自補的問題。
  • [x] 限制 HoT abilityId=0 只能回推到已確認的週期治療 status，多來源依 potency 權重拆分，無候選者保留為未歸屬列。
  • [ ] 檢查 action effect type 是否還有治療資訊不是 04，但不能把 1B 直接當 healing，因為 1B 大多是附加狀態 / ability id。

M4. Shield / D.Shield ​

Status: In progress

目標：維持 有效護盾(估)，不要誤稱正式 absorbs。

  • [x] 已用 HP loss 差值估算實際吸收量，只在可歸因到單一 active shield status 時列入。
  • [x] 移除不是 barrier 的 F38 / 764，加入 F34；Horoscope 762 / 763 僅作 overlap blocker。
  • [x] 多盾情境下，SCH 鼓舞 不再吃掉所有可吸收量；parserVersion 51 為 3.002M，FFLogs 3.085M。
  • [x] 普通 F36 不再誤算為中間學派護盾；F34 不再合成全隊狀態。
  • [ ] 對每筆 shielding estimate 輸出 debug reason：single shield / multiple shields / missing HP / no active shield。
  • [ ] 收斂 AST shield：目前 0.394M vs overlay 0.895M（FFLogs absorbs 0.937M），只補有逐事件證據的消耗。
  • [ ] 收斂 SCH 多盾歸因：目前約 3.002M vs overlay 3.5M（FFLogs absorbs 3.085M）。
  • [ ] 對比 overlay 的 D.Shield 時，標示為 estimate mismatch，不把它列為可 100% 對帳欄位。
  • [ ] 若未來能取得 ACT overlay 匯出資料，再研究是否能接近 overlay 的吸收歸屬。
